# Задания CI

`tasks` — очередь и результаты выполнения заданий.

Из webhook сохраняем `repository` (owner/name), `run_id`, `run_attempt`,
`commit_sha` (полный SHA) и `branch` (может отсутствовать).
Один запуск CI с одной попыткой создаёт одно задание: повторная доставка
не должна создавать дубликат. При добавлении использовать
`ON CONFLICT (repository, run_id, run_attempt) DO NOTHING`.

Сервер создаёт задание со статусом `queued`. Агент забирает самое старое
по `created_at, id`, в одной транзакции с `FOR UPDATE SKIP LOCKED` переводит
в `running`, увеличивает `attempts` и задаёт `started_at`.
`attempts` — число взятий задания агентом, `run_attempt` — попытка CI в GitHub.

После работы сохраняем `result` (текст отчёта) или `error`, итоговый статус
`succeeded` / `failed` и `finished_at`. Статус succeeded означает успешное
выполнение задания по заданным проверкам, а не автоматическое слияние PR.
Правила повторов и восстановления running после сбоя ещё не реализованы.

Docker выполняет `001_tasks.sql` автоматически только при создании новой базы.
Для существующей базы примените файл отдельно, не удаляя volume:

```powershell
Get-Content -Raw db/001_tasks.sql | docker compose exec -T postgres sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

Повторный запуск этого файла безопасен для неизменённой схемы. Будущие изменения
структуры оформляем отдельными SQL-миграциями: CREATE IF NOT EXISTS не обновляет
существующие столбцы. Методы добавления и получения задач пока не подключены.
