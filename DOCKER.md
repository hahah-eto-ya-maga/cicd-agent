# Запуск в Docker

Добавьте недостающие переменные из `.env.example` в существующий `.env`.
Не заменяйте сохранённый ключ API примером. Для PostgreSQL задайте пароль,
а для webhook — секрет, совпадающий с настройкой GitHub.

```powershell
docker compose up --build -d
docker compose logs -f
docker compose down
```

Проверка: `http://localhost:8080/health`.
Webhook: `http://localhost:8080/webhook`.
Для GitHub при локальной разработке направьте HTTPS-туннель на порт 8080.

nginx передаёт запросы на `server:8000`. Flask запускается через Gunicorn.
PostgreSQL доступен контейнерам как `postgres:5432`; его порт наружу не открыт.
Параметры подключения переданы серверу и агенту через переменные `PGHOST`,
`PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`.

Пока сервер только проверяет и логирует webhook, а агент ждёт с `task = None`.
Запись и чтение задач PostgreSQL, таблицы и скачивание репозитория ещё не реализованы.

Данные PostgreSQL и рабочие папки агента находятся в отдельных named volumes.
Обычный `docker compose down` их сохраняет. Флаг `-v` удаляет эти данные.
После создания базы смена `POSTGRES_PASSWORD` в `.env` не меняет пароль
существующего пользователя PostgreSQL.

Оба Dockerfile устанавливают Python-зависимости на этапе builder и копируют
готовое окружение в runtime. Файл `.env` не включается в образы.
Агент содержит Git; зависимости и изоляция для тестируемых проектов добавятся позже.

Текущий nginx принимает HTTP. Для постоянного размещения на сервере потребуется
настроить HTTPS с сертификатом. При внешнем HTTPS-туннеле Flask видит внутреннюю
схему HTTP; сейчас обработчик не строит внешние ссылки и редиректы.
